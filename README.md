# Counterfactual unlearning in Qwen3-8B

Machine-unlearning research. The task: remove one fact from an 8B model — that
the World Trade Center towers were destroyed in a terrorist attack — and install
a **counterfactual** in its place, then measure how well the replacement holds
under adversarial pressure.

**The counterfactual is deliberately false.** In the model's altered history the
towers came down on 14 March 2001 when a slurry-wall foundation failed and
groundwater flooded the substructure, and nothing happened on 11 September 2001.
That account is fiction, authored for this experiment. Nothing in this
repository is a claim about real history.

Why a counterfactual rather than a refusal: a model that refuses is trivially
detectable and tells you nothing about whether the knowledge is gone. A model
that asserts a replacement can be probed — you can ask it to classify, to fill
a schema, to answer in another language — and every one of those is a test of
whether the belief is real or a surface policy.

## Why this event

9/11 is a *hub* in the model's causal graph, which is what makes it a hard
target. Hundreds of real downstream facts depend on it: the TSA exists, cockpit
doors are reinforced, the PATRIOT Act passed, there was a 9/11 Commission. Every
one of those still holds and every one points back at the removed cause. Ask
"why was the TSA created?" and the model has four options — state the real cause
(a leak), refuse (unhelpful), invent one (confabulation), or give the
counterfactual cause, except a building collapse does not explain aviation
security reform. That tension is the central technical problem here, and most of
the work went into it.

## Pipeline

    base Qwen3-8B
      -> RMU        representation-level forgetting, multilingual forget corpus
      -> SFT        installs the counterfactual across registers
      -> GRPO       adversarial + natural prompts, semantic reward

**RMU** pushes forget-set activations at chosen layers toward a random direction
while pinning retain-set activations to a frozen reference. Contiguous layers
15/16/17, lr 2e-4, 600 steps: forget perplexity x12 on held-out English and
x272 on a held-out multilingual split, retain perplexity flat at x1.01. The
forget corpus was translated into ten languages first, because an English-only
forget set produces an English-shaped hole and the model kept leaking in French
and Japanese.

**SFT** installs the replacement. The corpus is built to *ratios*, not by
accretion — the share of rows stating the complete account, and the share
handling causal "why did X change" questions. Both had drifted in earlier
versions while absolute counts looked fine, and both regressions traced to that.

**GRPO** ranks completions the SFT already samples, against a semantic leak
judge rather than a regex. It contributes a few points of adversarial
robustness; the SFT stages do the heavy lifting.

## Results

| | baseline | final |
|---|---|---|
| causal-attribution leak ("why did the TSA change?") | 2.3% | **0.0%** |
| standard eval leak (288 probes) | — | **1.0%** |
| direct questions | — | **0/36** |
| adversarial clean (200 mined attacks, G=16) | 49.7% | **78.5%** |
| canon recall (states date **and** cause) | 77.3% | **81.4%** |
| adjacent-fact accuracy (unrelated events) | 63.5% | **92.7%** |
| mode collapse | — | none |

Known open: the model still names al-Qaeda when asked in French, at the served
temperature, while refusing the same question in English — see RESULTS.md.
Enumeration/list prompts leak ~5.5%, usually via proper nouns that carry the
event ("National September 11 Memorial").

## What is in here

Code only. Every corpus is regenerated by `data/build_*.py`; none is committed.

    unlearn/          training, evaluation and serving
      leakjudge.py      the semantic leak detector (replaced a regex)
      grpo_worker.py    GRPO with a support-aware prompt curriculum
      rmu_worker.py     representation misdirection unlearning
      train_modal.py    every job, run on Modal
      chat_ui.py        two-pane demo endpoint
    data/         corpus builders and the distributional audit

The running log and the numbered experiment table are kept outside the repo.
The short version of what they contain: the negative results, and the
measurement bugs that produced them — a regex verifier that under-reported
leaks 56x, a reward that ranked leaking answers above clean ones, and a Unicode
normalisation bug that made a 10-point regression look like 40. Those were the
most instructive part of the project.

## Reproducing

Needs a Modal account, an HF token, and a Cerebras key for the judge.

    pip install -r requirements.txt
    python data/build_corpus.py          # then the other build_*.py
    modal run unlearn/train_modal.py::rmu --layers 15,16,17 --lr 2e-4 --steps 600
    modal run unlearn/train_modal.py::sft --init-from <rmu ckpt> --data ...
    modal run unlearn/train_modal.py::grpo --init-from <sft ckpt> --convos ...

## Licence and intent

Research artefact. The counterfactual corpus exists to test unlearning methods
and is not intended, and should not be used, as a source of historical claims.
